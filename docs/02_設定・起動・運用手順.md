# 設定・起動・運用手順

## 1. 構成

| 部品 | 内容 |
|---|---|
| `app/collector` | Talknoteへの接続（Playwright）と、差分の収集（投稿・コメント・添付） |
| `app/parsing` | 本文の読み取り（`body.py`）、Excelの読み取り（`excel.py`）、数式の検証（`formula.py`） |
| `app/rules` | 院別の項目定義と読み取りルールの初版（DBに版管理して登録） |
| `app/targetdate.py` | 対象日の判定 |
| `app/pipeline.py` | 分類 → 観測値 → 採用値（二重計上防止）→ 不整合検出 → 日別状態 |
| `app/aggregate.py` | 月次・年次の集計、期間比較、率の計算 |
| `app/analysis.py` | 分析コメント（事実はプログラムで計算。AIは任意で仮説だけを書く） |
| `app/jobs.py` / `app/scheduler.py` | 定期実行（00:10 JST）、キュー、多重実行防止、補完 |
| `app/web` | 画面（FastAPI＋Jinja2） |
| `app/backup.py` / `app/notify.py` | バックアップ、通知 |
| `tests/` | サンプルデータ（架空）による自動テスト |

データの保存先は `APP_DATA_DIR`（既定 `var/`）です。

- `app.db`：SQLite
- `vault/`：暗号化した原文・添付の原本
- `backups/`：バックアップ

## 2. 初回セットアップ（Windows / Linux 共通）

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m playwright install chromium
.venv/Scripts/python -m app.cli init-env
.venv/Scripts/python -m app.cli init
.venv/Scripts/python -m app.cli create-admin admin
```

- Linux では `.venv/bin/python` を使い、`playwright install --with-deps chromium` を実行します。
- `init-env` は `.env` を作り、暗号鍵 `APP_SECRET_KEY` を生成します。
- `create-admin` はパスワードを対話で入力します。

> **注意**
> - `APP_SECRET_KEY` を変えたり失ったりすると、保存済みのパスワードや原文を復号できなくなります。`.env` はバックアップとは別の安全な場所にも保管してください。
> - このパソコンでは、Windowsのアプリ仮想化（AppData\Roaming 配下）が原因で仮想環境が壊れたため、仮想環境を `C:\Users\okita\.venvs\clinic-reports` に置いています。

## 3. 起動

```bash
python -m app.cli serve --host 0.0.0.0 --port 8100
```

- Web画面とスケジューラーが同じプロセスで動きます。
- スケジューラーは、毎日00:10（JST）の自動収集、15秒ごとのキュー処理、03:00のバックアップを行います。
- 同じDBに対してサーバーを2つ以上起動しないでください。多重実行はDBのロックで防いでいますが、無駄な処理になります。

起動後の手順は次のとおりです。

1. ブラウザで `http://サーバー:8100` を開き、管理者でログインします。
2. 「設定」の「Talknoteのログイン情報」に、IDとパスワードを入力して保存します。
3. 「稼働状況」の「接続テスト」で、ログインの可否と4院それぞれの取得可否を確認します。
4. 「設定」の「過去データの取得開始日」を決め、「稼働状況」の「期間を指定して再取得」で初回の取り込みをします。

## 4. 日常の運用（画面から）

| やること | 画面 |
|---|---|
| 前日の実績・異常の確認 | ダッシュボード、日次レポート |
| 本文とExcelの差異の確認、採用値の選択 | 確認キュー → 各項目 →「この値を採用」 |
| 手動補正（理由は必須、履歴に残る） | 数値をクリック → 抽出根拠 →「値を手動で補正する」 |
| 未提出・休診・取得失敗の確認 | 提出状況 |
| 開院日の設定（それより前は「開院前」で集計しない） | 設定 → 対象院・営業日 → 開院日 |
| 今すぐ収集／期間を指定して再取得／失敗分を再実行 | 稼働状況 |
| 読み取りルール変更後の再解析・再集計 | 設定 → 読み取りルール（保存時に再解析の開始日を指定）、または 稼働状況 →「再解析・再集計」 |
| CSV / Excel出力 | 日次・月次レポートのリンク |

## 5. エラーからの復旧

| 状況 | 画面での表示 | 対処 |
|---|---|---|
| ログイン切れ | 自動で再ログイン（追加の操作は不要） | — |
| パスワード変更・ログイン失敗 | 上部に「再認証が必要」と赤く表示 | 設定でパスワードを更新 → 接続テスト |
| 追加認証（認証コード） | 上部に「再認証が必要」と赤く表示 | 稼働状況 →「再認証を開始」→ 表示された画面を見て認証コードを入力 |
| 添付の取得失敗 | 稼働状況の「Excel失敗」 | 「失敗分を再実行」（最大5回まで自動で再試行） |
| Excelの書式変更 | 確認キュー「Excel書式変更・読取失敗」 | 設定 → 該当院のExcelルールで見出し文字を修正 → 再解析 |
| サーバーの停止 | — | 再起動すると、前回成功した範囲の続きから自動で補完 |

## 6. 本番稼働（利用者による契約・承認が必要な工程）

| 工程 | 状態 | 必要な作業・費用の目安 |
|---|---|---|
| 常時稼働サーバー | **未設定**（現在は開発用PCで稼働） | 国内VPS 2〜4GB（月 約1,500〜4,000円）。Ubuntuで2〜3章を実行し、systemdで常駐させる（`deploy/clinic-reports.service`） |
| HTTPS・アクセス制限 | **未設定** | 独自ドメイン（年 約1,500円〜）＋Caddy/nginx＋Let's Encrypt（無料）。社内IPに限定する場合はVPNかIP制限 |
| DB | SQLite（設定済み） | 利用者が少なければ SQLite で十分。PostgreSQL にする場合は `DATABASE_URL` を変更 |
| バックアップ | 毎日03:00に `var/backups` へ保存（14世代） | 別の場所への複製（VPSのバックアップ機能、オブジェクトストレージ 月 約300〜1,000円）は**未設定** |
| 障害の通知 | 画面に記録（設定済み） | メール（SMTPの設定）、Slack等のWebhook URL は**未設定** |
| AI要約 | **未設定**（定型文の要約で動作中） | `ANTHROPIC_API_KEY` を設定し、設定画面でオン（月 数百円程度の見込み） |

### Windows PC で常時稼働させる場合（暫定運用）

PCの電源が入っていてログオンしていれば、ブラウザを閉じても動き続けます。ただし、スリープ・シャットダウン・ログオフの間は止まります。止まっていた期間は、再開後に自動で補完します。

```bash
schtasks /Create /TN "ClinicReports" /SC ONLOGON /RL LIMITED /TR "\"C:\Users\okita\.venvs\clinic-reports\Scripts\pythonw.exe\" -m app.cli serve --port 8100" /F
```

作業フォルダの指定が必要なため、実際には `deploy/start_windows.cmd` をタスクに登録します。

## 7. Railway で稼働させる

1. GitHub のリポジトリから Railway のプロジェクトを作成します。`Dockerfile` と `railway.json` が自動で使われます。
2. サービスに **ボリューム** を追加し、マウント先を `/data` にします。DB・暗号化した原本・暗号鍵・バックアップはここに保存されます。
3. リージョンを **Southeast Asia（Singapore）** にします。
4. 「Networking」で公開ドメインを発行します。
5. 初回起動時のデプロイログに出る `[SETUP] 初回セットアップ用トークン` を控えます。`https://（ドメイン）/setup` を開き、トークンを入力して管理者を作成します。
6. 管理画面の「設定」でTalknoteのログイン情報を登録し、「稼働状況」で接続テストを実行します。
7. 取得開始日（例：2026-01-01）を設定し、「期間を指定して再取得」で過去データを取り込みます。

補足

- 暗号鍵（`APP_SECRET_KEY`）は、環境変数で指定しなければ `/data/secret.key` に自動で作成されます。ボリュームを消すと、保存データを復号できなくなります。
- サーバーは1台（レプリカ1）で動かします。スケジューラーは同じプロセス内で動きます。
- 費用の目安：Hobby プラン 月5ドル（使用量込み）＋超過分。メモリ約0.5〜1GB、ボリュームは1年分で約5GB。
